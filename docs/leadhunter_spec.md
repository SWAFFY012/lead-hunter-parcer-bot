# LeadHunter — Спецификация проекта

## Краткое описание

**LeadHunter** — это локальное десктопное приложение для macOS (M1), которое автоматизирует полный цикл лидогенерации: парсинг объявлений с OLX.ua → сохранение в мини-CRM → генерация персонализированных сообщений через локальный AI (Ollama) → рассылка через WhatsApp с нескольких аккаунтов. Разработано для веб-студии (сайты, Telegram-боты), запускается локально через браузер (localhost).

---

## Проблема

Ручной поиск клиентов на OLX занимает часы: открыть объявление, скопировать телефон, написать сообщение, переключить телефон, отправить — и так 100+ раз в день. Нет системы отслеживания — кто ответил, кто нет, кто забанил. Нет персонализации — одинаковые тексты банятся и игнорируются.

## Метрики успеха

- Возможность делать 200-500 исходящих контактов в день с 3-5 WA-аккаунтов
- Уровень бана аккаунтов < 10% в месяц
- Время на подготовку одной рассылки < 15 минут
- Полная история взаимодействия с каждым лидом

---

## Пользователь

**Один пользователь** — владелец веб-студии, технически грамотный (пишет Node.js боты), работает на MacBook M1. Запускает приложение локально, может закрыть крышку ноутбука.

---

## Пользовательский путь (Core Journey)

```
1. НАСТРОЙКА (один раз)
   └── Добавить WA-аккаунты → отсканировать QR → аккаунты сохранены

2. ПРОГРЕВ (1-2 недели для новых номеров)
   └── Задать план прогрева → приложение автоматически отправляет "живые" сообщения

3. ПАРСИНГ
   └── Вставить URL категории OLX → настроить параметры → запустить
   └── Приложение собирает: имя, телефон, заголовок, текст объявления, URL
   └── Автоматическое удаление дубликатов

4. ГЕНЕРАЦИЯ AI
   └── Выбрать базу лидов → выбрать/создать промпт-шаблон
   └── AI (Ollama) генерирует персонализированное сообщение для каждого лида
   └── Полуавтоматический режим: одобрить пачку из 10 → дальше идёт само

5. РАССЫЛКА
   └── Настроить: диапазон задержек, лимит в день, распределение по аккаунтам
   └── Запустить → мониторинг в реальном времени в UI
   └── Каждые 60 мин — отчёт в личный WA: "Отправлено 47, ответили 3, ошибок 1"

6. CRM
   └── Видеть статус каждого лида, историю сообщений, ставить теги/заметки
   └── Фильтровать: "все кто ответил за последние 3 дня"
   └── Экспортировать взаимодействия в CSV для анализа скриптов
```

## Функциональные требования

### P0 — Обязательно (MVP)

#### Модуль 1: Управление аккаунтами
- Добавление WA-аккаунтов через QR-код в UI (без терминала)
- Просмотр статуса аккаунтов: онлайн/оффлайн/забанен
- Удаление аккаунтов с очисткой сессии
- Отображение аватара и имени после авторизации

#### Модуль 2: Прогрев аккаунтов
- Настройка плана прогрева (сколько дней, сколько сообщений в день)
- Автоматическая рассылка "прогревочных" сообщений по случайным числам из contacts.txt
- Встроенная библиотека живых фраз (приветствия, ответы) с randomizer
- Имитация typing (30ms/символ) перед каждым сообщением
- Рандомизированные задержки Gaussian jitter (2-7 мин между сообщениями)
- Дашборд прогрева: день X из Y, сообщений сегодня: N

#### Модуль 3: Парсинг OLX
- Ввод URL категории OLX + количество страниц для парсинга
- Авторизация через сохранённый storageState.json (Playwright)
- Сбор данных: имя, телефон (клик "Показать телефон"), заголовок, текст объявления, URL
- Обнаружение и пропуск дубликатов по номеру телефона
- Прогресс-бар в реальном времени
- Stealth-режим: рандомные задержки 2-7 сек, скроллинг, движения мыши
- Статус парсинга: сколько собрано, сколько пропущено (дубли), ошибки

#### Модуль 4: База лидов (мини-CRM)
- Таблица лидов с колонками: Имя, Телефон, Источник, Дата, Статус, Аккаунт
- Статусы лида: Новый → Отправлено → Ответил → Заинтересован → Сделка / Отказ
- Теги и заметки для каждого лида
- Фильтрация по статусу, дате, аккаунту, источнику
- Полная история сообщений по лиду (лента)
- Автоотметки: Забанен, Ошибка доставки, Нет ответа 7 дней
- Экспорт в CSV (все лиды / выборка по фильтру)
- Экспорт вступивших в диалог — отдельно по каждой рассылке

#### Модуль 5: AI-генерация сообщений
- Редактор промптов с переменными: {{name}}, {{title}}, {{text}}, {{city}}
- Библиотека промптов (сохранить/загрузить/удалить)
- Отправка на локальный Ollama (http://127.0.0.1:11434/api/generate)
- Модель по умолчанию: llama3, настраивается в конфиге
- Полуавтоматический режим: пачка 10 → показываем в UI → "Одобрить всё" или редактировать каждое
- Spintax в шаблоне: {Привет|Добрый день|Здравствуйте}

#### Модуль 6: Рассылка
- Запуск рассылки по выбранной базе лидов
- Настройки: задержка между сообщениями (мин-макс), лимит в день на аккаунт
- Автоматическое равномерное распределение базы между аккаунтами
- Имитация typing перед каждым сообщением
- Проверка: номер зарегистрирован в WA? (не отправлять на незарегистрированные)
- Лог в реальном времени: кому отправлено, статус доставки, ошибки
- Пауза/Возобновление/Остановка рассылки
- Реакция на входящие (детект ответа → смена статуса лида)

#### Модуль 7: Мониторинг
- Отчёт в WA на личный номер каждые N минут (настраивается)
- Формат: "📊 LeadHunter: отправлено 47, ответили 3, забанено 0, ошибок 1"
- Dashboard на главной: сводка за сегодня, активные аккаунты, статус рассылки

### P1 — Желательно
- Поддержка нескольких URL OLX в одном парсинге (очередь)
- Расписание рассылки (запустить в 10:00, остановить в 18:00)
- Чёрный список номеров
- Fallback AI: если Ollama недоступна → OpenAI/Claude API
- Тёмная тема

### P2 — Приятно иметь
- Поддержка других источников парсинга через плагин-систему
- Telegram-уведомления вместо/в дополнение к WA-отчётам

| IPC | REST API + Socket.io | Реалтайм-лог в UI |
| Запуск | npm run dev → http://localhost:3000 | |

### Схема БД (SQLite)

```sql
CREATE TABLE leads (
  id INTEGER PRIMARY KEY,
  phone TEXT UNIQUE NOT NULL,
  name TEXT, title TEXT, ad_text TEXT,
  source_url TEXT, city TEXT,
  campaign_id INTEGER,
  status TEXT DEFAULT 'new',
  tags TEXT, notes TEXT,
  assigned_account TEXT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  last_contact_at DATETIME,
  ai_message TEXT
);

CREATE TABLE accounts (
  id TEXT PRIMARY KEY,
  phone TEXT, name TEXT, avatar TEXT,
  status TEXT DEFAULT 'offline',
  warmup_day INTEGER DEFAULT 0,
  daily_limit INTEGER DEFAULT 50,
  sent_today INTEGER DEFAULT 0,
  added_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE messages (
  id INTEGER PRIMARY KEY,
  lead_id INTEGER REFERENCES leads(id),
  account_id TEXT REFERENCES accounts(id),
  direction TEXT, content TEXT, status TEXT,
  sent_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE campaigns (
  id INTEGER PRIMARY KEY,
  name TEXT, prompt_id INTEGER,
  status TEXT DEFAULT 'draft',
  total_leads INTEGER, sent INTEGER DEFAULT 0,
  replied INTEGER DEFAULT 0,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE prompts (
  id INTEGER PRIMARY KEY,
  name TEXT,
  system_prompt TEXT,
  message_template TEXT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## Антибан система

| Механизм | Реализация |
|---|---|
| Gaussian jitter | Случайные задержки с нормальным распределением, не фиксированные интервалы |
| Typing simulation | sendPresenceUpdate('composing') → задержка 30ms/символ → отправка |
| Content variation | Spintax + переменные — каждое сообщение уникально |
| Session persistence | useMultiFileAuthState — без повторных QR |
| Gradual warmup | День 1-3: 10-20 сообщений; неделя 2: до 50 |
| No links cold outreach | Инструкция AI в промпте: не использовать ссылки в первом сообщении |

## План тестирования

### Фаза 1 — Изолированные модули
1. **Аккаунты:** Добавить тестовый номер → QR → статус online ✓
2. **Парсер:** 1 страница OLX → проверить данные в БД
3. **AI:** Промпт на 3 тестовых лидах → проверить уникальность сообщений
4. **Рассылка:** 3 сообщения на свои номера → проверить доставку и лог

### Фаза 2 — Интеграция
5. Полный цикл: парсинг (10 лидов) → AI → одобрение → рассылка
6. Смена статусов лидов при ответе
7. WA-отчёт на личный номер

### Фаза 3 — Нагрузка
8. 50 номеров × 2 аккаунта → мониторить скорость и ошибки
9. 7 дней прогрева на тестовом номере → проверить отсутствие бана
