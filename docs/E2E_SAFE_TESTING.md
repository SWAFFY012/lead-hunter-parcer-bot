# Safe E2E Testing Plan (План безопасного тестирования)

При первом запуске системы крайне важно не "спалить" рабочие WhatsApp-номера из-за багов в циклах или таймингах рассыльщика. Ниже представлен чеклист для безопасного E2E-тестирования.

## 1. Настройка Dry Run (Холостой режим)

Завтра первым делом мы должны реализовать режим **Dry Run**. 

В файле `backend/src/modules/sender/senderManager.js` необходимо обернуть физический вызов отправки сообщения в проверку настройки `dry_run_mode`:

```javascript
const isDryRun = getSetting('dry_run_mode') === 'true';

if (isDryRun) {
    console.log(`[DRY RUN] Would send to ${phone} from ${accountId}: ${text}`);
    // Имитация задержки отправки
    await sleep(2000); 
    // Имитируем успешную отправку
} else {
    // Реальная отправка
    await sock.sendMessage(jid, { text });
}
```

## 2. Пошаговый Чек-лист для Ручного Тестирования

### Шаг 1: Тест Парсера (Safe)
- Зайти в `/parser`.
- Вставить ссылку на раздел (например, "Разработка сайтов").
- Поставить лимит: 1 страница.
- Нажать "Start".
- **Ожидаемый результат:** В базе (`leads` table) появились 10-40 записей, имена очищены (сработала Sanitization), дубликаты проигнорированы. UI обновил Progress Bar.

### Шаг 2: Тест AI и Spintax (Safe)
- Зайти в `/ai`.
- Создать тестовый промпт со Spintax: `{Привет|Добрый день}, {{name}}! {Тест 1|Тест 2}.`
- Выбрать 5 лидов и нажать "Генерировать".
- **Ожидаемый результат:** В карточках лидов появилось уникальное сообщение. Ошибок OOM от Ollama не возникло. Текст должен быть уникальным (где-то "Привет", где-то "Добрый день").
- **Важно:** Сообщения должны быть в БД, но WhatsApp еще не участвует.

### Шаг 3: Тест Рассылки в Dry Run (Safe)
- Проверить в настройках, что `dry_run_mode = true`.
- Подключить 1 тестовый WhatsApp аккаунт (отсканировать QR).
- В `/sender` выбрать кампанию и тестовый аккаунт. Запустить рассылку.
- **Ожидаемый результат:** На дашборде ползет прогресс. В консоли бэкенда пишутся логи `[DRY RUN] Would send...`. Физически сообщения на телефон лидам **не приходят**.
- **Проверка таймингов:** Убедиться, что паузы между имитациями отправок соответствуют заданным в настройках (например, 120-300 секунд), а не отправляются мгновенно.

### Шаг 4: Тест Прогрева (Internal WhatsApp)
- Подключить 2 **своих** тестовых аккаунта.
- Выключить `dry_run_mode = false`.
- В `/warmup` запустить алгоритм прогрева.
- **Ожидаемый результат:** Два ваших телефона начнут переписываться друг с другом. 
- Проверить, что диалог выглядит как легитимный (задержки при печати, статус composing, прочтение сообщения). Убедиться, что скрипт останавливается при достижении `warmup_msgs_target`.

### Шаг 5: Боевой тест (1 сообщение)
- Создать кампанию ровно на 1 тестовый лид (ваш 3-й личный номер).
- Убедиться, что `dry_run_mode = false`.
- Отправить.
- **Ожидаемый результат:** Сообщение пришло на телефон. На телефоне отправителя отображается корректно. В CRM статус лида изменился на `sent`.
