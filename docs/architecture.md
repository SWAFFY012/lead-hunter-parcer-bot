# Архитектура LeadHunter (Cloud-First)

## Описание проекта
Система автоматизированного сбора лидов (Instagram, OLX) и генерации персонализированных AI-сообщений. Проект переходит от локальной монолитной архитектуры (где всё хранится на одном Mac) к распределенной облачной архитектуре для обеспечения доступа к CRM со смартфона.

---

## 1. Компоненты системы

Система состоит из трех основных модулей:

### 1.1 Облачная База Данных (Supabase)
Единый источник истины (Source of Truth) для всей системы. 
- **СУБД:** PostgreSQL.
- **Особенности:** Предоставляет готовый REST API. Не требует написания собственного бэкенда для обработки простых CRUD-запросов (чтение, добавление, обновление лидов).
- **Миграции:** Мак-приложение при запуске автоматически отправляет SQL-запросы для обновления структуры таблиц (добавление новых колонок, статусов), если это необходимо.

### 1.2 "Толстый клиент" (Mac App - Локально)
Рабочая станция, которая выполняет всю тяжелую работу, требующую браузеров и обхода блокировок.
- **Роль:** Сбор данных, AI-генерация, рассылка (при необходимости).
- **Технологии:** Node.js (PM2), Puppeteer, API Google Gemini / Ollama.
- **Рабочий процесс:** Парсит платформы, генерирует персонализированный текст и отправляет готовых лидов напрямую в Supabase по API. 

### 1.3 Мобильная CRM (Web App - Cloudflare Pages)
Урезанная веб-версия (только CRM), предназначенная для работы с телефона.
- **Роль:** Просмотр баз, ручная отправка реакций, ручная отправка сообщений, управление воронкой.
- **Технологии:** React / Vite.
- **Хостинг:** Cloudflare Pages (бесплатный хостинг для статики).
- **Доступ:** Открывается в браузере телефона, может быть добавлено на домашний экран (PWA) или встроено в Telegram Mini App.
- Связывается напрямую с Supabase, минуя Mac.

## 2. Структура репозитория (Monorepo)

Весь проект должен храниться в **одном репозитории на GitHub**. Дробить проект на части не нужно.

```text
leadhunter-monorepo/
├── backend/          # Локальный бэкенд для Mac (парсеры, AI, логика)
├── frontend-mac/     # Текущий интерфейс панели управления на Маке
└── mobile-crm/       # НОВЫЙ проект: легкая CRM для телефона
```

### Как деплоить на Cloudflare, если всё в одном репозитории?
Cloudflare Pages идеально поддерживает архитектуру монорепозиториев (когда много проектов в одной папке).
- Вы подключаете свой GitHub к Cloudflare.
- В настройках проекта на Cloudflare вы указываете **Root directory: `mobile-crm`**.
- Cloudflare автоматически будет игнорировать папки `backend` и `frontend-mac`. Он скачает код, зайдет в папку `mobile-crm`, сбилдит только её и выложит в интернет. Никаких `.cloudflareignore` файлов настраивать не нужно!

## 3. Воронка продаж и Статусы (Workflow)

Мобильная CRM будет ориентирована на ручную "дожимную" работу с Инстаграм-лидами.

### Новые статусы лидов в БД:
1. `parsed` — только спарсен, текста еще нет.
2. `ai_ready` — текст сгенерирован, ждет реакции.
3. `reaction_sent` — отправлена реакция/лайк в сторис.
4. `message_sent` — отправлено само AI-сообщение в Директ.

### Логика работы на телефоне:
1. **Экран "Свежие":** Выводятся лиды со статусом `ai_ready`.
   - Пользователь жмет "Открыть IG", ставит лайк.
   - Возвращается в CRM, жмет **"Реакция отправлена"**. 
   - В БД статус меняется на `reaction_sent`, а в поле `reaction_timestamp` записывается текущее время.
2. **Экран "В прогреве":** Выводятся лиды, у которых статус `reaction_sent`, но с момента `reaction_timestamp` прошло менее 24 часов. (Показывается таймер обратного отсчета).
3. **Экран "Пора писать":** Выводятся лиды, у которых прошло > 24 часов после реакции.
   - Пользователь копирует сгенерированный текст.
   - Жмет "Открыть IG", отправляет текст в Директ.
   - Жмет **"Сообщение отправлено"** — лид переходит в `message_sent` и уходит в архив.

## 4. План перехода (Роадмап)

1. **Фаза 1: Инфраструктура.** Создание бесплатного аккаунта Supabase и создание там копии текущей структуры базы данных.
2. **Фаза 2: Адаптация Mac.** Изменение кода бэкенда на Маке, чтобы он перестал писать в локальный файл `database.sqlite` и начал писать в Supabase.
3. **Фаза 3: Разработка Mobile CRM.** Создание легкого React-приложения `mobile-crm`, настройка связи с Supabase и деплой на Cloudflare Pages.
4. **Фаза 4: Тестирование.** Проверка синхронной работы: Мак парсит, лид тут же появляется на телефоне.
