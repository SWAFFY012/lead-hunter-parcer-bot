# ADVANCED ANTI-BAN STRATEGY & DEEP ARCHITECTURE
*Confidential Research Document: WhatsApp Anti-Spam Evasion & B2B Growth*

Данный документ описывает "подводную часть айсберга" алгоритмов Meta, отвечающих за блокировки в WhatsApp, и предлагает архитектурные решения для их обхода при использовании библиотеки Baileys.

---

## 1. Скрытые триггеры блокировок (Fingerprinting)

Алгоритмы Meta (WhatsApp Anti-Spam Heuristics) не ограничиваются жалобами пользователей. Они используют предиктивный анализ для выявления автоматизации до того, как аккаунт успеет отправить сообщение.

### 1.1 "Velocity Spike" (Всплеск скорости)
**Как работает фильтр:** Алгоритм отслеживает производную (скорость изменения) объема исходящего трафика. Если аккаунт 3 месяца молчал, а затем за 1 час отправляет 50 сообщений новым контактам — это триггер "Velocity Spike". Бан прилетает автоматически, даже если получатели не нажимали кнопку "Спам".
**Решение (Ramp-up Curve):**
Разгон (Ramp-up) должен быть логарифмическим, а не линейным. Если лимит 50 сообщений, они не должны уходить подряд. Пул отправки должен быть "размазан" по всему рабочему дню (с 09:00 до 19:00) с использованием Jitter-задержек.

### 1.2 Хеширование медиафайлов (Media Hash Blacklisting)
**Как работает фильтр:** WhatsApp вычисляет SHA-256 хеш каждого передаваемого изображения/видео. Если файл с идентичным хешем отправляется с разных аккаунтов или массово рассылается неизвестным контактам, хеш попадает в блэклист. Все аккаунты, отправляющие этот хеш, мгновенно теряют Trust Score.
**Программная уникализация (Решение):**
При отправке креативов через Baileys необходимо пропускать каждое изображение через библиотеку (например, `sharp`):
- Изменение качества JPEG на ±1-2%.
- Добавление невидимого шума (Gaussian noise 0.5%).
- Обрезка 1-2 пикселей с краев.
- Удаление/генерация случайных EXIF-метаданных.
В результате каждый получатель получает визуально идентичную, но криптографически уникальную картинку.

### 1.3 Изоляция IP-адресов и "Guilt by Association"
**Как работает фильтр:** По умолчанию все сессии Baileys (веб-сокеты) открываются с IP-адреса вашего сервера (часто это датацентр DigitalOcean/Hetzner, которые изначально имеют низкий траст у Meta). Если 5 аккаунтов сидят на одном IP и один получает бан, алгоритм помечает остальные аккаунты как "связанную ферму" (Guilt by association) и блокирует их превентивно.
**Решение:**
Маршрутизация каждой Baileys-сессии через индивидуальный **Mobile или Residential Proxy**.

## 2. Архитектура "Auto-Aging" (Матрица Уровней)

Для автоматического управления безопасностью, система должна сама высчитывать возраст аккаунта и применять к нему жесткие правила. Отсчет идет от даты привязки сессии (`added_at`).

| Tier | Статус | Срок жизни | Лимиты холодной базы | Лимиты прогрева | Разрешенные форматы |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Tier 0** | 🛡 Quarantine | `0 – 3 дня` | **0 сообщений** (Lockout) | 5–15 / день | Только текст |
| **Tier 1** | 🧪 Sandbox | `4 – 14 дней` | 10–15 / день | 15–30 / день | Текст, V-Card |
| **Tier 2** | 🔥 Warmed Up | `15 – 30 дней` | 25–40 / день | 30–50 / день | Текст, Опросы, Медиа |
| **Tier 3** | 👑 Veteran | `31+ день` | 50–70 / день | 50–70 / день | Любые (макс. траст) |

*Логика:* Если менеджер случайно добавит 100 лидов в кампанию и выберет аккаунт Tier 1, система физически не даст отправить больше 15 сообщений в эти сутки.

## 3. Инновационные форматы B2B Аутрича

Вместо классического текстового спама, Baileys позволяет использовать нативные интерактивные элементы WhatsApp. Они имеют высочайший Trust Score, так как спамеры редко заморачиваются с их реализацией.

### 3.1 Интерактивные Опросы (Polls)
Опросы — идеальный Ice-Breaker. Нажатие пользователем на вариант ответа в опросе алгоритмами Meta засчитывается как **полноценный входящий ответ**. Это моментально открывает 24-часовое диалоговое окно и обнуляет риск бана.
* **Пример B2B:**
  *Вопрос:* "Привет, {{name}}! Занимаемся сайтами для стройки. Какая сейчас главная проблема в вашем бизнесе?"
  *Варианты:* [1. Мало заявок] [2. Заявки дорогие] [3. У нас всё супер]
* **Технически в Baileys:** Использование `sendPollMessage()`.

### 3.2 Контактные карточки (V-Card Drop)
Отправка карточки контакта (`.vcf`) выглядит максимально органично и профессионально.
* **Пример B2B:** Отправляется 2 сообщения. Первое: "Привет! Видел вас на OLX. Мы делаем ботов. Оставлю свою визитку на всякий случай, сохраните, если будет актуально." Второе: Карточка контакта с вашим лого и сайтом внутри карточки.
* **Почему это работает:** Ссылки внутри V-Card не парсятся антиспам-фильтром так же агрессивно, как ссылки в голом тексте.

### 3.3 Audio Drops (Голосовые сообщения "как бы записанные сейчас")
Отправка заранее записанного голосового аудио (формат `.ogg`, кодек `opus`) с флагом `ptt: true` (Push-To-Talk). Для пользователя это выглядит так, будто вы прямо сейчас наговорили аудио специально для него. Конверсия в прослушивание B2B-войсов достигает 80%.

## 4. Техническое задание (Requirements) для Бэкенда

Чтобы интегрировать стратегию Auto-Aging в существующий код LeadHunter, потребуется сделать следующие доработки:

### Изменения в БД (`src/db/schema.sql`):
В таблицу `accounts` необходимо добавить:
1. `added_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP` (Для расчета возраста).
2. `proxy_url TEXT` (Для привязки Socks5/HTTP прокси к конкретной сессии).
3. `custom_tier INTEGER DEFAULT 0` (Возможность ручного переопределения уровня).

### Изменения в `src/modules/sender/senderManager.js`:
1. **Динамический расчет лимита:** Перед стартом рассылки вычислять: `daysAlive = (now - account.added_at) / 24h`. На основе `daysAlive` определять Tier (0, 1, 2, 3) и устанавливать `daily_limit` динамически, игнорируя глобальные настройки.
2. **Менеджер форматов:** Добавить поддержку передачи типа сообщения (Text, Poll, V-Card, Audio) из фронтенда и вызов соответствующих функций Baileys (например, `sendMessage(jid, { poll: { name: '...', values: [...] } })`).
3. **Smart Proxy Routing:** Прокидывать `proxy_url` при инициализации `makeWASocket` через кастомный `agent` (например, `https-proxy-agent`).

### Изменения в `src/modules/accounts/accountManager.js`:
При инициализации сессии Baileys внедрить обработку медиа "на лету" (в случае реализации рассылки картинок в будущем), добавляя микро-модификации буфера изображения перед отправкой.
